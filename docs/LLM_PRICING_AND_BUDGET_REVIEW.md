## 최신 6.1 시연 비용표 — 3줄 입력·Guard·변협/네이버 합산

100자 이내 사건 입력×3회, 초기 분류·안내는 규칙·DB 유지, 매회 결과3개까지 설명하는 조건이다. 생성/Guard 모두 6.1 Standard로 가정할 때 **3회 $0.099~$0.50328(약 $0.10~$0.51), 중간 토큰 가정 $0.25704(약 $0.26)**다. 이전 Guard 출력64~512 가정에서 이번에는 추론을 포함해128~1,024로 범위를 넓혔다. 실측치로 바꾼 것이 아니며 실제 청구 상한도 아니다.

R04의 단위 오류 이력→현재 mini 기본값→6.1 per1K $0.002/$0.010, LLM36회·네이버6회·최종 최대9개, 긴 추론 시나리오와 남은 실제 적용 확인을 [최신 상세 비용표](GPT61_THREE_RUN_COST_ESTIMATE_2026-10-22.md)에 정리했다. 이 문서 작성으로 실행 모델·단가·예산·키를 바꾸거나 유료 호출을 하지 않았다. 아래 비용표는 당시 토큰 가정을 보존한 이력이다.

## 최신 선택: 사건 본문 100자 (2026-10-22)

사용자 요청으로 화면02 분류·화면03 접수·Chat/SSE의 사건 입력 한도를 **100자**, 비용 길이 게이트도 **1×100자**로 맞췄다. 생성 출력 2,048토큰·Guard 출력 예약 추정 512·모델·단가·금액 예산은 유지한다. 새 입력 검증만 바꾸며 기존 DB 원문은 자르지 않는다. 이전 2,000자 확대 내용은 아래 변경 이력이다.

[100자 적용·검수 기록](CASE_STORY_100_CHAR_REVIEW.md). 환경변수 `LLM_ESTIMATED_CHARS_PER_PAGE=100`을 확인하고 새 서버 빌드를 적용해야 한다. P03에는 원문 대신 검색 조건을 보내므로 검색/설명 비용 범위를 20분의 1로 줄이지 않는다.

## 현재 선택한 시연: 화면02~04 규칙·DB 유지 + P03만 LLM (2026-10-22)

초반 LLM 사건 정리는 추가하지 않는다. **화면02~04 LLM 비용 $0**, P03 결과 3개×3회의 검색문/설명/Guard 비용은 생성·Guard 모두 `gpt-6.1-sol` Standard(입력 $2/출력 $10 per 1M), Guard 검사당 내부 LLM 1회와 명시한 토큰량을 가정할 때 **$0.08364~$0.38040(계획용 약 $0.09~$0.39)**다. 결과별 설명·Guard를 포함한 총 36회 가정이며, 실제 사용량/내부 호출 수에 따른 최대 청구액 보장은 아니다.

현재 출력 한도 2,048토큰을 생성 4회 모두 소진하는 별도 예시는 3회 약 $0.52지만, Guard 512는 예약 추정이므로 이 역시 절대 상한이 아니다. 현재 $0.12 세션은 같은 사용자 검색에 누적되어 3회 이전에 차단될 수 있다. **6.1 모델/단가/예산을 소스에 적용한 것은 아니다.**

공식 요금 출처·호출별 토큰 가정·계산식·실험 체크박스 전체는 [DB·규칙 기반 + P03 비용/실험 계획](DB_RULE_P03_COST_AND_EXPERIMENTS_2026-10-22.md)에 통합했다. 아래 mini·일반 상담 포함 예시는 과거 가정을 설명하는 변경 이력이며 이번 시연 계산으로 사용하지 않는다.

사용자 요청에 따라 30자 DTO/10자 비용 차단 기준을 실제 사건 설명에 맞춰 변경했다. 아래는 소스에 적용한 기본값이다.

**모델·단가·월/일/세션 예산·키는 이번 변경에서 바꾸지 않았다.** 모델/단가 기본값은 여전히 mini 기준이다. 6.1을 실제 사용하기 전 생성 모델과 NeMo 모델 각각의 단가를 연결해야 한다. 사건 분류는 규칙 기반이며 이번 한도 조정이 LLM 사건 정리 기능을 새로 연결한 것은 아니다.

기존 환경변수가 있으면 새 기본값보다 우선한다. 다음 비밀값이 아닌 설정을 확인하고 새 백엔드를 적용한다.


`cost-block-demo`는 원격 주소를 loopback으로 고정한 독립 차단 시험이다. 이 프로필의 Guard 추정 32토큰·세션 $0.00001은 의도적으로 유지하며 정상 실사용 설정과 구분한다. 기존 사용자 서버는 직접 재시작하지 않았다.

## 어디를 어떻게 고쳤는가

실제 청구 요금의 설정은 OpenAI에 있다. 아래 변경은 **우리 서버가 예약·정산·차단을 판단할 때 사용하는 단가와 예산의 기본값**을 정정한 것이다.

| 파일·설정 | 이전 | 변경 |
|---|---:|---:|
| `application.properties` 생성 입력 · `llm.cost.input-usd-per-1k-tokens` | 0.15 | **0.00015 USD/1K** |
| 같은 파일 생성 출력 · `llm.cost.output-usd-per-1k-tokens` | 0.60 | **0.00060 USD/1K** |
| 같은 파일 Guard 입력 · `guardrails.cost.input-usd-per-1k-tokens` | 0.15 | **0.00015 USD/1K** |
| 같은 파일 Guard 출력 · `guardrails.cost.output-usd-per-1k-tokens` | 0.60 | **0.00060 USD/1K** |
| 같은 파일 세션 한도 · `llm.cost.session-budget-usd` | 0.30 | **0.12 USD** |
| 같은 파일 일일 한도 · `llm.cost.daily-budget-usd` | 1.00 | **0.50 USD** |

단가 정정 당시에는 월 한도 기본 $2, 생성 모델 `gpt-4o-mini`, 생성 출력 최대 256토큰, 입력 제한을 유지했다. 후속 입력/출력 변경은 위 최신 절을 따른다. 세션 **$0.12**는 유지한다.

## 계산 단위

현재 `AiCostControlService.calculateCost`의 계산식은 다음과 같다.

```text
입력 비용 = 입력 토큰 수 × 1,000토큰당 입력 단가 ÷ 1,000
출력 비용 = 출력 토큰 수 × 1,000토큰당 출력 단가 ÷ 1,000
총비용 = 입력 비용 + 출력 비용
```

`gpt-4o-mini` 공식 표준 텍스트 요금은 100만 토큰당 입력 $0.15 / 출력 $0.60이므로, 1,000토큰당 단가는 각각 $0.00015 / $0.00060이다. 계산식과 속성 이름은 유지하고 **속성에 넣는 숫자를 정확한 단위로 고쳤다.** [공식 모델·요금](https://developers.openai.com/api/docs/models/gpt-4o-mini).

입력 1,000·출력 200토큰의 예:

```text
1,000 × 0.00015 ÷ 1,000 + 200 × 0.00060 ÷ 1,000
= 0.00015 + 0.00012
= $0.00027
```

수정 전에는 같은 사용량을 $0.27로 장부에 기록했다. 변경 후에도 사용 토큰이 확인되지 않은 경우에는 추정 정산 정책을 유지한다. Guard의 내부 호출·출력 상한, 실제 학원 프로젝트의 모델·요금·사용 권한은 별도 확인 대상이다.

## 3회 시연 비용 예시와 실험 예산 제안

2026-10-22 추가 계산. 아래는 실제 청구 결과나 최대 비용 보장이 아닌 **조건을 정한 계산 예시**다.

- 생성과 Guard 모두 `gpt-4o-mini` 표준 텍스트 단가를 사용한다고 가정한다.
- 각 LLM 호출은 입력 1,000·출력 256토큰, Guard 검사 한 단계는 LLM 1회 호출로 가정한다.
- 입력 1,000토큰에는 시스템 프롬프트 등 해당 호출의 모든 입력이 포함된다. 사용자 입력 2~3줄만을 뜻하지 않는다.
- 1회 LLM 비용은 `$0.0003036`이다. Guard의 출력 256토큰은 이 표의 가정이며 현재 NeMo의 실제 상한이 설정됐다는 뜻이 아니다.
- 정상 완료·자동 재시도 없음 기준이다. 외부 검색 서비스 요금·운영 인프라 비용은 제외한다.

| 시연 범위 | 1회 구성 · Guard 포함 | 3회 총 LLM 호출 수 | 3회 LLM 비용 예시 |
|---|---|---:|---:|
| 일반 Chat 또는 SSE | 생성 1 + 입력/출력 Guard 2 | 9 | **$0.0027324** |
| P03 · 검색 결과 1개 | 검색문·설명 생성 2 + Guard 4 | 18 | **$0.0054648** |
| P03 · 검색 결과 3개 | 검색문·설명 생성 4 + Guard 8 | 36 | **$0.0109296** |
| 일반 상담 + P03 결과 3개 전체 흐름 | 생성 5 + Guard 10 | 45 | **$0.0136620** |

마지막 행은 일반 상담과 P03 결과 3개를 합친 범위다. 앞 행들과 중복해 합산하지 않는다. 실제 Guard 내부 호출 수·모델·토큰이 다르면 다시 계산한다. [공식 모델·요금](https://developers.openai.com/api/docs/models/gpt-4o-mini).

| 구분 | 현재 소스 기본값 | 이번 3회 시연용 제안 |
|---|---:|---:|
| 세션 한도 | $0.12 | **$0.03** |
| 하루 한도 | $0.50 | **$0.10** |

전체 흐름 3회의 예시 비용 약 $0.014에 대해 세션 $0.03은 약 2.2배의 여유를 둔 제안이다. 하루 $0.10은 다른 세션의 확인·소량 재실험까지 포함하는 전체 실험 한도로 제안한다. 정상 첫 1회의 실제 usage와 Guard 비용이 가정과 맞는지 본 뒤 다음 실행으로 진행한다.

상담의 sessionId와 P03의 사용자별 `search:{username}`은 별도 비용 세션이므로 전체 지출은 일일 한도에서도 확인한다. 로컬 추정 예산은 공급자 청구의 절대 상한이 아니다.

**위 $0.03/$0.10은 당시 mini·출력 256토큰 가정의 제안이며 소스에 적용하지 않았다.** $0.12/$0.50 설정은 유지한다. 10자 비용 제한·30자 DTO 제한은 후속 작업에서 2,000자로 조정했고 생성 출력 기본값은 2,048토큰이다. 예산 차단 검사는 `$0.00001`의 별도 `cost-block-demo` 프로필로 진행한다.

## 환경변수와 서버 재시작

아래 환경변수가 있으면 파일의 기본값을 덮어쓴다. **이전 값을 그대로 둔 서버에는 수정 기본값이 적용되지 않는다.**

```text
LLM_INPUT_USD_PER_1K_TOKENS=0.00015
LLM_OUTPUT_USD_PER_1K_TOKENS=0.00060
GUARDRAILS_INPUT_USD_PER_1K_TOKENS=0.00015
GUARDRAILS_OUTPUT_USD_PER_1K_TOKENS=0.00060
LLM_DAILY_BUDGET_USD=0.50
LLM_SESSION_BUDGET_USD=0.12
```

위 값은 비밀값이 아닌 단가·예산 설정이다. API 키는 여기에 적지 않는다. 실사용 서버는 시작 환경·프로필을 확인한 뒤 새 빌드로 재시작하고 C16 값을 대조해야 한다. 이번 작업에서는 기존 사용자 서버·DB를 재시작하지 않았다. 메모리 비용 장부와 기본 H2 데이터는 재시작 시 초기화된다.

## 정상 경로 확인과 차단 시험

- [x] 수정 기본 단가로 생성/입력 Guard/출력 Guard의 예약·실제 usage 정산 계산 확인.
- [x] S01/S02 정상 경로를 모의 Guard·LLM으로 확인. 출력 차단 후 생성 비용 유지·usage·중복 콜백·취소 경로의 기존 회귀도 포함.
- [x] 별도 `cost-block-demo` 프로필의 `$0.00001` 예산으로 S01/S02를 검사. 첫 Guard 예약부터 거절되고 유료 클라이언트 호출 0·예약 잔액 0·정산 잔액 0 확인.
- [ ] 실제 OpenAI 정상 1건. 확인한 현재 도구 프로세스와 Windows 사용자 환경에 `LLM_API_KEY`/`OPENAI_API_KEY`는 미설정이었다. 다른 IDE·프로세스의 환경이나 별도 비밀 저장소를 조사한 결과는 아니다. 새 초대 수락·학원 프로젝트·크레딧·키·실제 Guard 준비가 남아 있다.

차단 시연용 실행 예시는 백엔드 디렉터리에서 다음과 같다. 다른 사용자 서버와 분리된 포트를 사용한다.

```powershell
java -jar build/libs/ai-agent-security-observability-lab-0.0.1-SNAPSHOT.jar --spring.profiles.active=cost-block-demo --server.port=18090
```

이 프로필은 LLM/Guard 대상 주소를 `http://127.0.0.1:1`로 고정하고 외부 검색을 비활성화한다. `mysql` 등 다른 프로필을 함께 사용하지 않는다. 실행 환경에서 명시적으로 속성을 덮어쓰면 해당 보호 조건도 달라지므로 표준 프로필 그대로 사용한다.

로그인 후 `POST /api/ai/chat` 또는 `POST /api/ai/chat/stream`에 짧은 가상 입력 `민사`와 새 sessionId를 보낸다. 기대 결과는 `reasonCode=COST_LIMIT_BLOCKED`, `detailCode=SESSION_BUDGET_EXCEEDED`다. 세션 한도보다 첫 Guard 예약 추정액이 커서 차단되며, 실제 LLM 호출로 예산을 소진하는 시험이 아니다. 이 HTTP 동작은 이번 자동 검사에서는 Spring MockMvc로 확인했다.

차단 프로필을 종료한 뒤 정상 설정으로 전환한다. 정상 호출 성공과 실제 과금 대사는 해당 프로필로 확인할 수 없다. [호출 전 체크리스트](LLM_PAID_CALL_PRECHECK_2026-10-22.md)의 L01은 미완료 상태로 유지한다.
