## Security Architecture Summary
위험 요청·반복 공격·비용은 호출 전에, 개인정보는 출력 전에 확인합니다.
### Fixed Guard | 요청 내용 검사
탈옥·프롬프트 주입·법률 위해·비밀/API 키 요청·인증 우회 등을 규칙으로 검사합니다.
차단된 요청은 답변 생성으로 진행하지 않습니다.
### Dynamic Guard | 같은 세션의 위험 누적
sessionId별 위험 점수·반복 횟수로 세션을 제한합니다.
화면13의 요청 위험 패턴 권고와 대화 누적 제한을 구분해 보여줍니다.
### Cost Control | 예산·예약·정산
입력 길이와 출력 상한을 제한하고, 유료 단계의 비용을 예산과 비교해 예약합니다.
이미 실행한 단계는 차단·오류 후에도 정산 대상으로 남깁니다.
### Privacy Output Guard | 출력 보호
응답·SSE 출력 경로에 개인정보 패턴 마스킹을 적용합니다.
의뢰인 응답에서 내부 메모를 제외합니다. 모든 개인정보 탐지를 보장하는 것은 아닙니다.

## 차단 이유를 읽을 수 있어야 합니다.
HTTP 상태와 함께 정책 사유·세부 사유·보호 결과를 확인합니다.
### 고정 정책 사유
BLOCKED_JAILBREAK · BLOCKED_PROMPT_INJECTION · BLOCKED_LEGAL_HARM
BLOCKED_SECRET_REQUEST · BLOCKED_AUTH_BYPASS
### 비용·반복 사유
COST_LIMIT_BLOCKED / REQUEST_TOO_LONG: 공통 비용 사유와 세부 길이 사유를 구분합니다.
DYNAMIC_SESSION_BLOCKED: 기존 세션의 누적 차단 상태를 나타냅니다.
### 개인정보 보호 예시
이름·전화번호·주민번호·계좌번호 등 지원 패턴과 필드의 표시를 마스킹합니다.
PII_OUTPUT_MASKED는 보호 결과 표시로 읽으며, 모든 요청의 reasonCode라는 뜻은 아닙니다.

## 쉬운 운영 관리 · Boards
마케팅·보안 대응·고객·변호사 업무를 권한별 보드로 쉽게 관리합니다.
### 01 마케팅 보드
문의·검색·현재 상담 준비와 유형·지역 분포를 봅니다.
상담 후 전환·이탈 분석은 별도 더미 시연으로 구분합니다.
### 02 보안 현황·처리 보드
차단·비용·개인정보 보호·위험 이력을 확인합니다.
Incident 확인·종결로 필요한 운영 조치를 기록합니다.
### 03 고객 보드
선택형 접수·준비 자료 안내·검색 요청을 제공합니다.
초기 안내는 규칙·템플릿이며 저장 문의는 접근 권한을 확인합니다.
### 04 변호사 보드
배정 문의의 사건·자료·원하는 도움을 확인합니다.
상태 변경·내부 상담 메모로 상담 준비를 이어갑니다.

## 직관적인 실시간 보안 관측·대응 시스템
이상 신호를 한눈에 파악하고, 근거를 확인해 필요한 대응으로 연결합니다.
### 01 실시간 보안 관측
현재 차단·비용 지표와 시간별 신호 변화를 확인합니다.
실시간은 Prometheus 수집·화면 갱신 주기 기준입니다.
### 02 위험 근거를 쉽게 확인
신호 조합과 위험 이력을 연결해 원인을 살펴봅니다.
요청80점 차단 권고와 대화 누적100점 등 세션 제한을 구분합니다.
### 03 운영자의 대응
위험 요약 → 상세 근거 → Incident 확인·종결로 이어갑니다.
관측 화면이 모든 위험에 자동 대응한다는 뜻은 아닙니다.
### 04 숫자를 정확히 해석
결측과 실제0, 실사용·추정·진행 예약 비용을 구분합니다.
사유 코드·마스킹 결과·LLM 호출 방지 지표를 함께 읽습니다.
