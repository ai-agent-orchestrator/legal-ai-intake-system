## Security Architecture Summary
위험 요청·반복 공격·비용은 호출 전에, 개인정보는 출력 전에 확인합니다.
### Fixed Guard | 요청 내용 검사
탈옥·프롬프트 주입·법률 위해·비밀/API 키 요청·인증 우회 등을 규칙으로 검사합니다.
차단된 요청은 답변 생성으로 진행하지 않습니다.
### Dynamic Guard | 같은 세션의 위험 누적
sessionId별 위험 점수·반복 횟수로 세션을 제한합니다.
화면13의 요청 위험 패턴 권고와 대화 누적 제한을 구분해 보여줍니다.
### Cost Control | 예산·예약·정산
입력 길이와 출력 상한을 제한하고, 유료 단계의 비용을 예산과 비교해 예약합니다.
이미 실행한 단계는 차단·오류 후에도 정산 대상으로 남깁니다.
### Privacy Output Guard | 출력 보호
응답·SSE 출력 경로에 개인정보 패턴 마스킹을 적용합니다.
의뢰인 응답에서 내부 메모를 제외합니다. 모든 개인정보 탐지를 보장하는 것은 아닙니다.

## 차단 이유를 읽을 수 있어야 합니다.
HTTP 상태와 함께 정책 사유·세부 사유·보호 결과를 확인합니다.
### 고정 정책 사유
BLOCKED_JAILBREAK · BLOCKED_PROMPT_INJECTION · BLOCKED_LEGAL_HARM
BLOCKED_SECRET_REQUEST · BLOCKED_AUTH_BYPASS
### 비용·반복 사유
COST_LIMIT_BLOCKED / REQUEST_TOO_LONG: 공통 비용 사유와 세부 길이 사유를 구분합니다.
DYNAMIC_SESSION_BLOCKED: 기존 세션의 누적 차단 상태를 나타냅니다.
### 개인정보 보호 예시
이름·전화번호·주민번호·계좌번호 등 지원 패턴과 필드의 표시를 마스킹합니다.
PII_OUTPUT_MASKED는 보호 결과 표시로 읽으며, 모든 요청의 reasonCode라는 뜻은 아닙니다.

## Boards And Dashboards
고객·변호사·관리자는 자기 업무와 권한에 맞는 화면을 봅니다.
### 고객 | 안내와 접수
선택한 내용을 정리하고 준비 자료를 안내합니다.
초반 안내는 규칙 기반이며 저장·검색은 인증과 문의 접근 권한을 확인합니다.
### 변호사 | 사건 검토 보드
배정 문의의 사건 유형·당사자 위치·자료·원하는 도움을 확인합니다.
상태 변경과 내부 상담 메모로 상담 준비를 이어갑니다.
### 관리자 | 마케팅·운영 보드
접수·검색 요청·현재 상담 준비 수와 유형 분포를 봅니다.
상담 후 전환·이탈 예시는 별도 더미 시연 모드로 표시합니다.
### 관리자 | 보안·비용·위험 요약
차단·비용·마스킹·호출 방지 지표와 위험 이력을 확인합니다.
화면13은 신호 조합을 운영자가 이해할 수 있는 위험 패턴으로 묶습니다.

## Observability
현재 확인할 수 있는 수치와 아직 수집하지 않는 값을 분리합니다.
### 문의 흐름 | 실제 DB 집계
문의 수·사건 유형별 분포·검색 요청 수·현재 상담 준비 수를 조회합니다.
단계별 수 차이를 실제 고객의 중도 이탈률로 단정하지 않습니다.
### 보안·비용 | 실제 관측 지표
Fixed·Dynamic·Cost 차단, Privacy 마스킹, LLM 호출 방지 등을 확인합니다.
실사용·추정 사용·정산·진행 예약 비용을 구분합니다.
### 화면13 | 위험 패턴과 근거
반복 차단·위험행동·외부전송 위험 신호를 요약합니다.
C16 지표·실제 시계열과 C17 위험 이력을 연결해 점검을 돕습니다.
### 전환 분석 | 더미와 향후 실측
상담 후 계약 전환·이탈 사유는 더미 데이터 시연입니다.
실측하려면 상담 결과·고객 여정·수집 동의·집계 기준을 추가로 설계해야 합니다.
