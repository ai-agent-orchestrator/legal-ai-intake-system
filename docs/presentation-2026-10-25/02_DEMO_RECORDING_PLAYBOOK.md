# 시연 대본 · 녹화와 편집

> **최신 기준:** [기존8분 + 화면10 마케팅 검증1분, 총9분 편집](09M_MARKETING_SECURITY_EDIT.md). 보안4분을 유지하고 마케팅 증거07:45–08:45 후 모바일로 마무리합니다. 아래 발표 혼합 대본과 관리자 Dashboard 촬영표는 이전 구성안입니다.

2026-10-25 / 발표·녹화용 현행 요약. 원문 Ground Rule 및 현행 코드·검수 결과 기준.

## 01. 6분30초 시연의 한 문장

“고객의 첫 설명을 상담 준비로 바꾸고, 위험과 비용을 관리자의 언어로 보여줍니다.”

### 녹화 순서
전체를 한 번에 찍기보다 USER / 검색 / 변호사 / 실패 / 관리자 / 모바일의6클립으로 촬영합니다.

### 검증 표기
더미·모의 공급자 표시는 유지합니다. 기존 저장 결과 조회와 지금 새로 실행한 검색을 구분합니다.

### 강조 장면
화면13에 가장 긴 시간을 배정합니다. 화면09~12는 각 역할을 짧게 보여주고13으로 연결합니다.

### 편집 기준
실제 클릭·응답·사유를 남깁니다. 로딩은 줄일 수 있지만 실패를 정상 응답처럼 붙이거나 모의 응답을 실호출처럼 편집하지 않습니다.

## 02. 컷1~3 | 문제와 고객 여정

입력 예시: “돈을 빌려줬는데 돌려받지 못했어요. 계약서와 이체 내역이 있어요.”

### 00:00~00:30 | PM 오프닝
화면: 표지 → 고객/사무소 문제 / 내레이션: “법률 문제를 처음 겪는 고객과 초기 응대가 바쁜 사무소를 연결합니다. 상담 전에 정보를 정리하고, 운영 중 위험과 비용까지 확인하는 서비스입니다.” / 자막: 상담은 더 명확하게. AI 운영은 더 안심되게.

### 00:30~01:25 | USER 접수
화면: 화면01 → 02 → 03 → 04 / 내레이션: “사건을 짧게 입력하면 규칙과 저장된 절차 정보로 먼저 안내합니다. 초반부터 매번 LLM에 원문을 보내지 않습니다.” / 자막: 짧은 입력 → 준비할 자료가 보이는 안내

### 01:25~02:20 | 검색 흐름
화면: 화면05의 시연 검색 요청1번 / 내레이션: “조건으로 검색문을 만들고 변협 도메인 대상과 일반 웹 결과를 함께 모읍니다. 출처와 설명을 구분하고 같은 요청 번호로 다시 확인합니다.” / 자막: 원문 근거를 확인할 수 있는 공개 정보 탐색

> USER user로 로그인. 검색 결과의 [모의] 제목을 지우지 않습니다. 네이버 실키 준비 전에는 실제 검색 적중 시연으로 말하지 않습니다.

## 03. 컷4~5 | 담당자와 필수 실패

실패는 서비스의 약점 대신 안전한 경계를 설명하는 장면으로 구성합니다.

### 02:20~03:20 | LAWYER 업무
화면: 화면06 목록 → 08 상세 → 07 메모 / 내레이션: “담당 변호사는 배정 문의만 검토합니다. 내부 메모를 작성하고 상태를 바꾸며, 동시 수정은 충돌을 알린 뒤 입력을 보존합니다.” / 자막: 담당자에게 필요한 정보만, 내부 검토는 분리

### 03:20~04:00 | 필수 실패 장면
화면: 비로그인401 / 다른 USER403 / 오래된 저장409 / 내레이션: “로그인이 없으면 저장을 멈추고, 다른 의뢰인의 자료는 차단합니다. 오래된 화면이 최신 내용을 덮어쓰지 않게 합니다.” / 자막: 정상 동작뿐 아니라 안전한 중단까지

> 401: 비로그인 저장.403: user2가 문의1번 조회.409: 같은 문의를 두 탭에서 연 뒤 먼저 다른 탭에서 저장. 입력 보존 후 “확인 후 편집 계속”까지 촬영.

## 04. 컷6~7 | 위험과 비용이 보이는 운영

화면13을 대표 상품 장면으로 배치합니다.

### 04:00~04:40 | 보안·비용
화면: 보안/비용 카드 → 화면11 C16 / 내레이션: “생성 전 위험 검사를 하고, 각 유료 단계의 예약·정산·잔여 예산을 확인합니다. 출력이 차단돼도 이미 사용한 비용은 남습니다.” / 자막: Guardrail까지 포함한 비용 통제

### 04:40~05:40 | 대표 화면13
화면: 09 요약 → 10 관심 분야 → 12 Incident → 13 확대 / 내레이션: “관리자가 지표 이름을 외울 필요는 없습니다. 반복 시도와 외부 접근 위험을 조합해 보여주고, 요청 점수와 대화 누적을 분리해 확인합니다.” / 자막: 지표를 나열하지 않고, 대응할 위험을 보여줍니다.

> C16 실사용·추정·예약은 모의 usage를 앱이 실제 계산한 값입니다. 공급자 실제 청구가 아닙니다. 요청80점 권고와 누적100점 제한은 합산하지 않습니다.

## 05. 컷8~9 | 모바일과 PM 마무리

소스·화면·검수 증거가 같은 이야기를 하도록 마무리합니다.

### 05:40~06:10 | 모바일
화면: 390px 화면02/03/07 컷 / 내레이션: “같은 흐름을 좁은 화면에서도 사용할 수 있도록 검수했습니다. 이 장면은 실제 휴대폰 접속이 아닌390px 브라우저 검수입니다.” / 자막: PC에서 모바일 화면까지 이어지는 접수 흐름

### 06:10~06:30 | 종료
화면: PM 검증 요약 카드 / 내레이션: “서비스 흐름, 권한, AI 보안, 비용, 관측을 연결했습니다. 다음 단계는 실제 공급자 사용량과 검색 품질을 같은 기준으로 대조하는 것입니다.” / 자막: 설계에서 운영 검증까지 연결하는 Technical PM

> 마케팅 보조 문구: “더 나은 상담은 더 명확한 첫 질문에서 시작됩니다.” / “위험은 차단하고, 이유는 남기고, 비용은 확인합니다.”

## 06. 오늘은 OBS + Clipchamp를 추천합니다

ChatGPT는 대본·자막·컷 구성 검토에 활용합니다.

### 녹화 | OBS
1080p·30fps, 브라우저 창 캡처, 마이크 음량 확인. 설정 마법사 후20초 시험 녹화로 글자·음성·개인 알림을 확인합니다. 설치가 없다면 Clipchamp 화면 녹화로 바로 시작해도 됩니다.

### 편집 | Clipchamp
여섯 클립을 순서대로 배치 → 대기/실수 부분 자르기 → 한국어 자동 자막 교정 → 핵심 문구만 강조 →1080p MP4로 내보내기.

### ChatGPT 활용

### 민감정보 없는 촬영
