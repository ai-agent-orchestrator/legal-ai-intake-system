키/Guard 준비가 끝나지 않으면 실제 호출을 반복 시도하지 않고 그 시간에 로컬 모의 검증과 보완 재현을 진행한다. 위 시간표는 작업 배분이며 성공을 보장하는 예상 완료 시간이 아니다.

## LLM 연결 준비 순서

1. [실제 호출 전 체크리스트](LLM_PAID_CALL_PRECHECK_2026-10-22.md)의 R01~R10을 확인한다. 초대/프로젝트 잔액과 정확한 API 모델 ID를 확인한다. 코딩 도구의 모델 이름을 그대로 추정 입력하지 않는다.
2. [서버 설정 예시](../backend/guardrail-ready-policy-checker/.env.example)의 빈 모델/단가/자격 증명을 실제 백엔드 실행 환경에 설정한다. 이 파일은 설명용이며 Spring이 자동으로 읽지 않는다. NeMo의 실제 호출 키·모델·출력 상한도 별도 확인한다.
3. 키는 서버 환경변수 또는 비밀 저장소에 보관한다. React `VITE_*`, 소스, Postman 공유 파일, 스크린샷, 명령 인수, 로그에 넣지 않는다. [공식 OpenAI 인증 지침](https://developers.openai.com/api/reference/overview).
4. `SEARCH_MAX_RESULTS=1`, 동시 실행1개·자동 재시도 없이 시작한다. 모델과 실제 적용 단가를 맞추고 C16 예산/진행 예약 기준값을 기록한다. 소스의 mini 단가를 다른 모델 비용으로 사용하지 않는다.
5. 가상 사건으로 문의·검색 요청을 생성한다. 같은 `searchRequestId`에 P03을 한 번 실행하고 C07로 상태와 결과를 조회한다. 원본 제목/URL/요약과 LLM 설명을 구분한다.
6. usage·단계별 정산·예약 종료와 공급자 사용량을 대조한다. 실패했을 때는 오류 분류를 먼저 하고 재호출한다. 실제 호출 전에는 ‘연결 성공’ 또는 ‘실측 비용’으로 기록하지 않는다.
