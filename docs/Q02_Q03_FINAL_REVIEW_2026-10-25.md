### Q02 화면05

**수정한 결함:** 저장 응답이 유실된 후 ‘최신 저장 정보 조회’가 실패해도 `finally`에서 `checked=true`가 되어 편집·재저장을 허용했다. C06/C08의 중복 저장 위험을 높이는 동작이었다.

- 재조회 시작 때 이전 성공 표식을 지운다.
- GET이 성공하고 현재 화면이 살아 있을 때만 ‘중복 가능성 확인 후 편집 계속’을 제공한다.
- 실패·취소 때 저장 잠금과 입력을 유지한다. POST를 자동 재전송하지 않는다.
- 이미 성공한 조회 뒤 다시 조회에 실패해도 이전 성공 표식으로 잠금을 풀지 않는다.
- C06·C08·P03 각각의 실패 재현 3개와 P03 연타 단일 POST 검사 1개를 추가했다. 수정 전 새 실패 재현 3개가 실패하고, 수정 후 모두 통과했다.

`IntakeSearchPage.jsx`만 제품 동작을 수정했다. API 계약·서버·DB·검색 공급자·실제 유료 실행 설정은 변경하지 않았다.

실제 격리 Spring에 문의·검색 요청·수동 결과를 저장한 뒤 **응답만 브라우저에서 유실**시켰다. 같은 문의/조건/검색 ID 재조회와 중복 저장 방지 수동 복구를 확인했다. P03 PARTIAL→설명 재시도→COMPLETED 및 새 페이지/재로그인 복귀는 브라우저의 로컬 응답 fixture로 확인했다. 실제 외부 검색 또는 실제 공급자 설명을 성공시켰다는 증거는 아니다.

기존 React 검사에는 RUNNING 폴링, 화면 이동 시 진행 중 GET 취소·이전 결과 숨김, 부분 출처 경고·안전 URL·미설정·권한·빈 결과 검사도 포함된다. C06/C08 서버에 새 멱등 API를 추가하지 않았으므로 사용자 확인 후 새로운 POST를 하면 중복 가능성 자체가 사라지는 것은 아니다.
