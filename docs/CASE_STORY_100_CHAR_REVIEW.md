# 사건 본문 100자 적용·검수

2026-10-22 (Asia/Seoul). 사용자가 간단한 사건 접수·시연에 맞춰 100자를 선택했다. 화면02~04는 기존 DB·규칙·템플릿 방식을 유지하며 초반 LLM 사건 정리는 추가하지 않는다.

| 항목 | 현재 |
|---|---|
| 화면02 분류·화면03 등록 | 사건 본문 최대 100자, 동일한 화면/서버 검증 |
| Chat/SSE | 공통 사건 입력 DTO 최대 100자 |
| 비용 길이 게이트 | 기본 1페이지 × 100자 |
| 생성 출력 / Guard 출력 예약 | 2,048토큰 / 512토큰 유지 |
| 검색문·결과 설명·메모·선택 필드 | 별도 기존 한도 유지 |
| 기존 DB·저장 원문 | 스키마 변경·절단 없음 |

100자는 핵심 상황 입력용이다. 금액·발생일·지역·자료 종류 등은 별도 입력 필드로 보완한다. 공백·줄바꿈 포함 UTF-16 단위이며 이모지는 두 단위 이상일 수 있다.

예시(68자):

> 지인에게 500만원을 빌려줬는데 약속한 날짜가 지나도 못 받았어요. 차용증과 이체 내역이 있고, 서울에서 상담받고 싶어요.

- [x] C02: 100자 통과·101자 거절·미저장.
- [x] C03: 100자 저장·101자 거절, 거절된 요청은 새 DB 행을 만들지 않음.
- [x] Chat/SSE: 100자 정상 검사 경로, 101자는 유료 클라이언트 실행 전 DTO에서 거절.
- [x] React: 100자 카운터·최대 길이·입력 보존·수정값 재등록·101자 요청 전 차단.
- [x] 별도 50자 비용 정책: DTO 이내 51자로 길이 차단·Dynamic 누적 회귀 확인.
- [x] 백엔드 194/194·bootJar, 프런트 138/138·Vite build 통과.
- [ ] 기존 실행 서버에 새 빌드 적용·활성 환경변수 확인. 이번에는 사용자 서버를 재시작하지 않았다.
- [ ] 최신 100자 설정의 직접 브라우저·모바일 실기기 확인. 이번 검증은 자동 테스트와 빌드다.

현재 환경변수가 기본값보다 우선한다. `LLM_ESTIMATED_CHARS_PER_PAGE=100`을 확인한다. 과거 2,000자 또는 10자 값이 남아 있으면 별도 정책이 적용된다. 이미 100자를 넘는 저장 데이터를 조회하거나 표시할 때 원문을 자동으로 자르지 않는다.

모델·단가·월/일/세션 예산은 변경하지 않았다. 화면02~04에는 LLM 비용이 없고, P03은 사건 원문 대신 검색 조건을 사용하므로 사건 입력 상한을 줄였다고 검색문·Guard·설명 비용이 같은 비율로 줄어드는 것은 아니다. 실제 유료 호출은 하지 않았다.
