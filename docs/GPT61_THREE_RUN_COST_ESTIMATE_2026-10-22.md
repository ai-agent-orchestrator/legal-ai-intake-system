# 6.1 · 3줄 사건 입력 × 3회 + 변협·네이버 검색 비용

2026-10-22 (Asia/Seoul). **과금 전 계획표이며 실측 청구서가 아니다.** 현재 소스의 호출 구조와 공식 단가를 확인해 계산했다. 실제 OpenAI/NeMo/네이버 키 호출은 실행하지 않았다. 이 문서 작성으로 실행 모델·단가·예산을 변경하지 않았다.

**계획 범위: 3회 전체 약 $0.10~$0.51, 중간 토큰 가정 $0.25704(약 $0.26).** 더 긴 추론을 고려한 별도 시나리오는 약 $0.64~$0.89다. 이 숫자는 절대 청구 상한이나 측정된 평균이 아니다. 첫 1회 실제 usage를 받은 뒤 범위를 갱신해야 실측에 가까워진다.

## 1. R04 · 단가 정정 내역과 6.1 실험 기준

모든 표의 입력/출력 단가는 **1,000토큰당 USD**다. 최초 단위 오류 수정과 모델 변경에 따른 단가 선택을 구분한다.

| 대상 | 최초 잘못된 기본값 | mini 단위 정정값 · 현재 소스 기본 | 6.1 실험에 사용할 환산값 |
|---|---|---|---|
| 생성 입력 / 출력 | $0.15 / $0.60 | $0.00015 / $0.00060 | **$0.002 / $0.010** |
| Guard 입력 / 출력 | $0.15 / $0.60 | $0.00015 / $0.00060 | **Guard도 6.1이면 $0.002 / $0.010** |

`gpt-6.1-sol` Standard, 272K 이하 입력 구간의 공식 단가는 **100만 토큰당 입력 $2 / 출력 $10**이다. [공식 모델·요금](https://developers.openai.com/api/docs/models/gpt-6.1-sol).

```text
USD = 입력 토큰 × 0.002 / 1,000 + 출력 토큰 × 0.010 / 1,000
```

- 생성 모델과 실제 NeMo 모델이 모두 6.1인 경우를 계산했다. Guard가 다른 모델이면 그 모델의 실제 단가로 해당 행을 다시 계산한다.
- 현재 `application.properties`, `CostedGuardrailService` fallback, `nemo-colang/config.yml`은 mini 기본값이다. 이 문서의 6.1 환산은 실행 서버 적용 완료를 뜻하지 않는다. 모델만 바꾸고 mini 단가를 유지하면 장부가 과소 계산한다.
- 6.1 적용 시 생성의 `LLM_MODEL`, `LLM_INPUT_USD_PER_1K_TOKENS`, `LLM_OUTPUT_USD_PER_1K_TOKENS`와 Guard의 `GUARDRAILS_COST_MODEL`, `GUARDRAILS_INPUT_USD_PER_1K_TOKENS`, `GUARDRAILS_OUTPUT_USD_PER_1K_TOKENS`를 각각 확인한다. Guard 장부 모델 이름 변경과 NeMo 실제 실행 모델 변경은 별개다. 비밀 키는 문서에 적지 않는다.
- 캐시 할인·Fast/Ultrafast·지역 처리·중계 수수료를 적용하지 않은 Standard 텍스트 예시다. 실제 계정의 적용 요금은 별도 대조한다.

## 2. 이번에 계산한 전체 서비스 범위

**3줄, 공백·줄바꿈 포함 최대 100자**의 가상 사건 3개를 각각 접수하고, 각 사건에서 새 검색 요청을 하나씩 실행한다.

```text
사건 입력 → 화면02 규칙 분류 → 화면03 DB 저장 → 화면04 규칙·템플릿 안내
→ C06 검색 요청 생성 → P03 명시적 실행
→ 입력 Guard → LLM 검색문 1회 → 출력 Guard
→ 네이버 변협 대상 1회 + 네이버 일반 웹 1회
→ 정제·중복 제거·최대3개 저장
→ 결과별 입력 Guard → LLM 관련성 설명 → 출력 Guard
→ C07/P02 조회·화면 표시
```

처음 사건을 LLM으로 다시 정리하는 호출은 없다. 화면02~04의 LLM 토큰 비용은 $0이다. 원문 대신 분야·분쟁·광역 지역·허용된 선호 조건을 P03에 전달한다. 시스템 프롬프트·검색 조건·결과 제목/요약·Guard 프롬프트가 추가되므로 입력 100자만 요금 계산에 넣지 않는다.

| 입력 예시 | 본문 |
|---|---|
| 1 · 대여금 | 지인에게 500만원을 빌려줬는데 약속한 날짜가 지났어요.<br>차용증과 이체 내역이 있습니다.<br>서울에서 상담받고 싶어요. |
| 2 · 양육비 | 이혼 후 양육비를 받지 못하고 있어요.<br>판결문과 미지급 내역이 있습니다.<br>부산 지역 변호사 상담을 원해요. |
| 3 · 보증금 | 전세 계약이 끝났는데 보증금을 돌려받지 못했어요.<br>계약서와 반환 요청 문자가 있습니다.<br>경기도에서 상담받고 싶어요. |

이 문장들의 실제 분류·검색·청구를 실행했다는 뜻은 아니다. 각각 100자 이내, 3줄인지 로컬에서 확인한 실험용 입력이다.

## 3. 네이버 + 변협 합산 검색은 어떻게 호출하는가

**검색 API 제공자는 네이버 하나**이며 변협은 검색 대상 출처다. 현재 코드는 변협 직접 API를 별도로 호출하지 않는다.

| 단계 | 사건 1회 | 사건 3회 | 가져오거나 처리하는 내용 |
|---|---:|---:|---|
| LLM 검색문 생성 | 1회 | 3회 | 분야·분쟁·광역 지역을 반영한 기본 검색문. 두 출처마다 따로 유료 생성하지 않음 |
| 네이버 변협 대상 검색 | 1회 | 3회 | 기본 검색문에 `site:klaw.or.kr`을 서버에서 붙여 `/v1/search/webkr.json` 호출. 요청 `display=3`, `start=1` |
| 네이버 일반 웹 검색 | 1회 | 3회 | 같은 기본 검색문으로 같은 API 호출. 요청 `display=3`, `start=1` |
| 검색 API 합계 | **2회** | **6회** | 응답 items의 title/link/description 수집. OpenAI 내장 web search 도구 호출 아님 |
| 병합 전 후보 | 최대 6개 | 최대 18개 | 변협 응답은 실제 URL 도메인 확인. 부적합 URL·빈 제목·중복 등을 제외하므로 적어질 수 있음 |
| 최종 저장·설명 | **최대 3개** | **최대 9개** | URL 중복 제거 후 공식 출처 우선 교대 병합. 양쪽에 충분히 있으면 기본 2개 공식+1개 일반 |

예를 들어 기본 검색문이 `서울 민사 대여금 변호사`이면 첫 요청은 여기에 `site:klaw.or.kr`을 붙이고 두 번째는 기본 검색문으로 보낸다. 이는 호출 구조 예시이며 실제 LLM 출력/검색 결과는 아니다. 일반 검색에서도 변협 URL이 나올 수 있어 두 응답의 출처가 완전히 분리되는 것은 아니다.

네이버 공식 문서는 검색 API 일일 한도를 25,000회, 오픈 API를 약관에 따라 무료 제공한다고 설명한다. **해당 무료 오픈 API 계약·쿼터를 사용하는 조건에서 위 6회 검색의 추가 요금은 $0**으로 계산한다. 실제 발급 서비스가 다른 유료 상품·이관된 요금제이면 그 계약을 먼저 확인해야 한다. [웹문서 검색 문서](https://developers.naver.com/docs/serviceapi/search/web/web.md), [요금 FAQ](https://developers.naver.com/products/intro/faq/faq.md).

변협 직접 유료 API 호출은 코드에 없으므로 그 항목의 호출 요금도 없다. 다만 공식 출처 결과가 0개일 수 있고 최종 9개가 모두 개별 변호사 프로필이라는 보장은 없다. 자격·경력·광고 여부는 원문으로 확인한다. 한쪽 장애는 결과·출처 경고를 보존하고, 불필요한 자동 재검색은 하지 않는다.

## 4. Guard 합산 호출 수와 과금 범위

정상 완료·결과 3개·자동 재시도 없음·**Guard 검사 한 단계가 내부 LLM 1회**라는 가정이다. NeMo 내부 다중 호출 여부는 실제 추적으로 확인해야 한다.

| 과금 단계 | 사건 1회 | 사건 3회 | 3회 짧은 출력 가정 | 3회 중간 가정 | 3회 길어진 출력 가정 |
|---|---:|---:|---:|---:|---:|
| 화면02~04 규칙·접수·안내 | LLM 0 | LLM 0 | $0 | $0 | $0 |
| LLM 검색문 구성 | 1 | 3 | $0.00684 | $0.01308 | $0.02436 |
| LLM 결과 설명 | 3 | 9 | $0.03744 | $0.07308 | $0.13716 |
| 입력 Guard | 4 | 12 | $0.02736 | $0.08544 | $0.17088 |
| 출력 Guard | 4 | 12 | $0.02736 | $0.08544 | $0.17088 |
| **Guard 합계** | **8** | **24** | **$0.05472** | **$0.17088** | **$0.34176** |
| 네이버 검색 2종 합계 | 2 | 6 | $0 조건부 | $0 조건부 | $0 조건부 |
| **전체 LLM 합계** | **12** | **36** | **$0.09900** | **$0.25704** | **$0.50328** |

Guard 합계 행은 입력/출력 행의 소계다. 총액에 다시 중복해 더하지 않는다. 네이버 $0은 위 무료 오픈 API 계약 조건이다. 서버·DB·네트워크 운영비는 계산하지 않았다. 로컬 Fixed/Dynamic Guard 점수 계산에는 LLM 토큰 비용이 없다.

### 토큰 가정 — 실측된 토큰 수가 아님

| 호출 1개 기준 | 짧은 출력 · 입력/출력 | 중간 · 입력/출력 | 길어진 출력 · 입력/출력 |
|---|---:|---:|---:|
| 검색문 생성 | 500 / 128 | 900 / 256 | 1,500 / 512 |
| 결과 설명 | 800 / 256 | 1,500 / 512 | 2,500 / 1,024 |
| Guard 검사 | 500 / 128 | 1,000 / 512 | 2,000 / 1,024 |

입력은 호출별 시스템 지시문·검색 조건·해당 결과·검사 프롬프트를 포함한 가정이다. 출력은 보이는 한국어 문장/True·False뿐 아니라 과금되는 **추론 토큰**을 포함한다. [공식 추론 토큰 과금 설명](https://developers.openai.com/api/docs/guides/reasoning?api-mode=chat).

로컬에서 실제 Java 검색문/설명 프롬프트와 합성 조건 JSON의 문자·UTF-8 바이트 크기도 계산 파일에 남겼다. 이 크기는 6.1 tokenizer나 공급자 usage가 아니며, NeMo가 실행 시 추가하는 내용·모델 추론량을 측정하지 못한다. 따라서 이를 실측 비용으로 표시하지 않는다.

### 직전 비용표보다 범위가 넓어진 이유

직전 약 $0.09~$0.39는 Guard 출력 64~512토큰 가정이었다. 이번에는 6.1의 비가시 추론과 **Guard 512가 원격 상한이 아닌 점**을 반영해 128~1,024토큰 시나리오를 썼다. 실험 결과가 바뀐 것이 아니라 계획 가정을 더 명확히 한 것이다. 100자로 줄였다고 고정 프롬프트·Guard·검색 결과 설명 비용이 같은 비율로 줄지는 않는다.

## 5. 긴 추론·실패 재시도의 별도 시나리오

| 3회 전체 시나리오 | 조건 | 계산 예시 |
|---|---|---:|
| 생성 출력 한도 소진 + Guard 1,024 | 1회 입력 총25,000, 생성4회 각각2,048, Guard8회 각각1,024 | **$0.64152** |
| 생성 출력 한도 소진 + Guard 2,048 | 같은 입력, 생성4회 각각2,048, Guard8회 각각2,048 | **$0.88728** |

현재 생성 출력 2,048은 요청 한도지만, Guard 512는 예약 추정이다. 위 $0.64~$0.89 역시 최대 청구액 보장이 아니다. Guard 추가 내부 호출·더 긴 출력·timeout 후 usage 미확인·수동 재실행이 있으면 증가한다. 출력 차단이나 실패가 앞서 생성한 비용을 취소하지 않는다. 추론만 하다가 출력 한도에 도달하면 보이는 답변이 없어도 과금될 수 있다.

**실험 순서:** 준비 확인 → 결과1개 정상 호출 → 실제 호출 수/usage/모델/비용 대조 → 결과3개 × 3회. 최초 확인 1건과 실패 재실험은 위 3회 총액 밖의 추가 비용이다. 3회 확인용 여유 자금 $1은 계획용이며 강제 청구 상한을 뜻하지 않는다.

현재 소스 예산 월 $2/일 $0.50/세션 $0.12는 변경하지 않았다. P03의 `search:{username}` 세션은 요청 ID가 달라도 누적된다. 중간 가정 3회 약 $0.26이므로 현재 세션 $0.12에서는 중간에 차단될 수 있다. 긴 출력 가정은 일 $0.50 부근이므로, 품질 시연과 예산 차단 실험을 구분하고 첫 usage 후 진행 예산을 결정한다.

## 6. 실측으로 바꾸기 위해 남길 값

- [ ] 생성/실제 NeMo 모델 모두 6.1인지, 1K 단가 $0.002/$0.010이 서버 장부에 적용됐는지 확인.
- [ ] 서로 다른 C06 요청 3개에서 searchRequestId·executionId, 네이버 두 요청의 성공/결과 수, 저장 결과 수를 기록.
- [ ] 검색문·각 설명·입력 Guard·출력 Guard의 실제 호출 수와 usage(추론 포함)를 각각 기록.
- [ ] C16 REPORTED/ESTIMATED·예약 종료 및 공급자 사용량을 대조. 미확인 usage를 실제 0으로 취급하지 않음.
- [ ] 첫 실측으로 이 표의 토큰 가정을 교체하고 2·3회 진행 여부 결정.
